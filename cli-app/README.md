# spec-it

Turn an idea into a `REQUIREMENTS.md` a coding agent can build from, plus clickable mockups. spec-it reads your project, looks at how others solve the problem, then asks you only the questions that change what gets built, one at a time, in a local web app.

It runs on the coding agent you already have and are signed into, so you don't need an API key. Claude Code, Codex, Gemini CLI, GitHub Copilot CLI, OpenCode, Cursor, Qwen, Goose, or any [ACP agent](https://agentclientprotocol.com/overview/agents) all work. An API key from Anthropic, OpenAI or Google works too.

## Install

```bash
npm install -g spec-it-app
```

Requires Node.js 20 or later, plus at least one agent CLI you're logged into (for example, run `claude` once and log in). Or use an API key.

## Use

Run it inside your project folder:

```bash
cd my-project
spec-it
```

It opens `http://127.0.0.1:4317/?t=…` in your browser:

1. Choose **Use my CLI login** (no key) or **API key**.
2. Pick the agent (or the provider and key) and the project folder.
3. Type the idea, choose a model, and press Start. Answer the questions as they come.

The output goes to `my-project/spec-it/<name>/`: `REQUIREMENTS.md`, plus `mockups/` (UI screens, an API reference, or CLI transcripts).

| Option | |
|---|---|
| `--project <dir>` | project folder (default: current folder) |
| `--port <n>` | port (default 4317, or any free port if that one is taken) |
| `--no-open` | don't open the browser |
| `--skill <dir>` | use your own copy of the spec-it skill |
| `-v`, `-h` | version, help |

## Privacy and security

- **Local only:** the app listens only on `127.0.0.1`, not on your network. The launch link carries a one-time token. Every request and WebSocket checks it, and WebSockets also check the origin.
- **CLI login mode:** spec-it runs your own installed agent CLI with its own login. It never reads or stores your credentials.
- **API keys:** kept in memory for one run, passed to the agent only as an environment variable, and never written to disk or logged.
- **No accounts or telemetry:** spec-it sends nothing anywhere. Your agent talks to its own provider as usual.

## How it connects

| Agent | Route | Sign-in |
|---|---|---|
| Claude Code | Claude Agent SDK | Claude Code login, or `ANTHROPIC_API_KEY` |
| Codex, Gemini CLI, Copilot CLI, OpenCode, Cursor, Qwen, Goose | Agent Client Protocol (ACP) over stdio | Each CLI's own login, or its API-key variable |
| Anything else on the ACP list | "Custom ACP agent" with its launch command | Its own |

ACP agents get a small injected MCP server with one tool, `ask_user`. That's how spec-it's multiple-choice questions reach the browser.

## Developing

This folder is the package source. The web UI is a React + shadcn/ui app in `ui/` (preset `b38nIpxD6`). **Only its production build, `ui/dist`, ships to npm.** The React source, `node_modules` and tests stay out.

```bash
npm run setup        # install server + UI deps, build ui/dist
npm start            # run from source
npm run dev:ui       # Vite dev server with live reload; proxies /api, /files, /ws to :4317
```

| Path | |
|---|---|
| `bin/spec-it-app.mjs` | the `spec-it` command |
| `src/server.mjs` | HTTP + WebSocket on 127.0.0.1, token-protected; serves `ui/dist` |
| `src/session.mjs` | one run: event log, pending questions and approvals, output scan |
| `src/agents.mjs` | agent registry and PATH detection (edit launch commands here) |
| `src/adapters/` | `claude-sdk.mjs`, `acp.mjs` |
| `src/agent-info.mjs` | live model list, account and plan usage (spends no tokens) |
| `src/mcp-bridge.mjs` | stdio MCP server injected into ACP agents |
| `ui/` | React source: `views/`, `components/app/` (Trace, Questionnaire, MessageScroller…), `hooks/use-run.ts` |
| `skill/` | generated by `npm run sync-skill` from `../.claude/skills/spec-it`, without `evals/` |
| `test/mock-acp-agent.mjs` | fake ACP agent for testing without tokens (use it as a Custom ACP agent) |

### Publishing

```bash
npm login
npm publish          # prepack: sync skill → build UI → check-pack → pack
```

`scripts/check-pack.mjs` stops the publish if the tarball would contain UI source (`ui/src`, `.tsx`), `node_modules`, the skill's evals or tests, or is missing `ui/dist/index.html` or `skill/SKILL.md`. Preview the contents with `npm pack --dry-run`.
